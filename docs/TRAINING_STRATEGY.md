# 모델 학습 전략 (TRAINING_STRATEGY)

마이스터즈 AI 사진 검수에서 "학습"이 언제, 무엇을, 어디서 필요한지 정리합니다. 결론부터 말하면 **파일럿과 첫 정확도 측정까지는 학습이 없고**, 측정 결과에 따라 두 종류의 로컬 모델 학습을 단계적으로 검토합니다.

---

## 1. 현재 구조: 학습 없이 동작하는 이유

| 검사 축 | 판단 주체 | 학습 여부 |
|---|---|---|
| 사진 품질 (흐림·노출·해상도) | 수치 규칙 | 없음. 임계값만 조정 |
| 부정 제출 (중복·재사용·위치·시각) | 해시·EXIF 규칙 | 없음 |
| 체크리스트 (필수 컷·전후 쌍) | 설정 파일 + 컷 분류 | 없음 |
| 시공 하자·컷 분류 | 범용 비전 언어 모델 (Claude 기본, Ollama 폴백) | **없음**. 카테고리 파일의 하자 설명을 읽고 판단 |

범용 비전 모델은 "전선 피복이 벗겨져 심선이 보임" 같은 설명만으로 해당 장면을 찾습니다. 따로 학습하지 않아도 되는 대신, 성능은 **설명의 품질과 임계값**에 좌우됩니다. 그래서 학습보다 측정과 설정 조정이 먼저입니다.

---

## 2. 단계별 전략

```
0단계 측정  →  1단계 설정 조정  →  2단계 예시 사진  →  3단계 이상 탐지 학습  →  4단계 로컬 VLM 미세조정
 (필수)         (필수)              (필요 시)           (고정 구도 컷에서 필요 시)   (로컬 전환이 필요할 때)
```

### 0단계. 측정 (학습 아님, 필수)

- **목적**: 어떤 하자 유형이 안 잡히는지, 오탐이 어디서 나는지 숫자로 확인. 이 수치가 없으면 이후 어떤 단계도 효과를 판단할 수 없습니다.
- **데이터**: 작업 종류당 검수 완료 작업 50건 이상(불합격 20% 이상). 검수 큐에서 사람이 판정을 남기면 자동으로 쌓입니다.
- **절차**: `python training/export_eval_set.py --category <id>` → `python training/evaluate_eval_set.py --category <id>`
- **산출물**: 판정 정확도, 컷 분류 정확도, 하자 코드별 정밀도·재현율 리포트(`report_*.json`).
- **다음 단계 기준**: 하자 코드별 재현율 0.8 미만 또는 정밀도 0.7 미만인 항목이 다음 단계 대상.

### 1단계. 설정 조정 (학습 아님, 필수)

- **대상**: 카테고리 파일(`config/categories/<그룹>/<id>.yaml`)의 하자 설명(`defect_rubric[].description`), 기본 심각도, 확신도 기준(`verdict.min_defect_confidence`), 품질 임계값.
- **방법**: 미탐은 설명을 현장 용어와 실제 장면 묘사로 구체화("보온재 없음" → "동관이 은색·금색 맨 금속으로 노출, 검은 보온재 없음"). 오탐은 설명에 제외 조건을 추가하거나 심각도를 낮춤.
- **비용**: 코드 변경 없음, 재시작만. 바꿀 때마다 0단계 리포트로 재측정하고 `PROMPT_VERSION`을 올립니다.

### 2단계. 예시 사진 제공 (few-shot, 학습 아님, 필요 시)

- **조건**: 설명을 고쳐도 특정 하자가 계속 안 잡힐 때.
- **방법**: 하자별 대표 사진 2~3장(정상 1장 + 불량 2장)을 프롬프트에 함께 보내 "이런 장면이 해당 하자"라고 알려줍니다. 사진당 입력 토큰이 늘어 비용이 약 2~3배가 되므로 문제가 되는 카테고리에만 적용합니다.
- **상태**: 현재 코드에는 없음. 필요해지면 카테고리 파일에 `examples:` 항목을 추가하고 프롬프트 빌더에 반영하는 작은 작업입니다(캐시 가능 블록에 넣으면 반복 비용은 줄어듭니다).

### 3단계. 이상 탐지 학습 (로컬 모델, 고정 구도 컷)

- **조건**: 매번 같은 제품·같은 구도로 찍히는 컷(실외기 거치대, 분전반 내부, 정수기 하부 연결부 등)에서 범용 모델이 놓치는 **미세한** 결함(볼트 누락, 작은 균열)을 잡아야 할 때.
- **모델**: Anomalib PatchCore 또는 EfficientAd. 정상 사진만으로 학습하고 정상 분포에서 벗어나면 점수를 냅니다. 코드 포함(`training/train_folder.py`, `backend/detector.py`).
- **데이터**: 컷당 정상 사진 30장 최소, 100장 권장. 촬영 가이드(프레임 오버레이)로 구도를 고정해야 성능이 나옵니다. 폴더 규격은 `docs/DATA_SPEC.md` §2.
- **장비·시간**: GPU 1장이면 수십 분. CPU도 가능(PatchCore 기준 1시간 내외).
- **역할**: 판정은 하지 않고 **검토 필요 트리거**(보조 근거)로만 씁니다. 현장 사진은 구도가 달라지면 바로 오탐이 나므로 주 판정으로 쓰지 않습니다.
- **적용**: 카테고리 파일에 `anomaly: {enabled: true, model_key: <폴더명>, shot_types: [<컷 id>]}`.

### 4단계. 로컬 비전 언어 모델 미세조정 (로컬 모델, 로컬 전환 시)

- **조건**: 개인정보 정책으로 사진을 외부로 보낼 수 없거나, 비용·속도 때문에 Claude 대신 로컬 모델을 주 모델로 써야 하는데 로컬 모델(Qwen2.5-VL 등)의 0단계 측정 결과가 기준에 못 미칠 때.
- **방법**: 우리 사진 + 검수 판정(+하자 라벨)으로 오픈 비전 모델을 LoRA 등으로 미세조정해 Ollama로 서빙. 서비스 쪽은 `INSPECTOR_VLM_PROVIDERS=ollama`, `INSPECTOR_OLLAMA_MODEL=<모델명>` 설정만 바뀝니다.
- **데이터**: 라벨된 사진 수천 장 단위(하자 코드당 수백 장). 0단계 평가 세트를 꾸준히 쌓는 것이 곧 이 단계의 학습 데이터입니다.
- **장비**: 사내 GPU(DGX Spark 등). 학습과 서빙을 같은 장비에서 할 수 있습니다.
- **순서**: 가장 뒤. 데이터가 충분히 쌓이고 로컬 전환 결정이 난 뒤에만 착수합니다.

## 3. 한눈에 비교

| 단계 | 학습? | 모델 | 어디서 | 데이터 | 비용·기간 | 지금 코드에 |
|---|---|---|---|---|---|---|
| 0 측정 | 아니오 | - | 우리 서버 | 검수 완료 50건/카테고리 | 토큰 비용만, 반나절 | 있음 |
| 1 설정 조정 | 아니오 | Claude/Ollama | 설정 파일 | 0단계 리포트 | 0, 즉시 | 있음 |
| 2 예시 사진 | 아니오 | Claude/Ollama | 프롬프트 | 하자별 사진 2~3장 | 토큰 2~3배 | 소규모 추가 필요 |
| 3 이상 탐지 | 예 (로컬) | Anomalib | 우리 GPU/CPU | 정상 사진 30~100장/컷 | 수십 분~1시간 | 있음 |
| 4 VLM 미세조정 | 예 (로컬) | Qwen2.5-VL 등 | 우리 GPU | 라벨 사진 수천 장 | GPU 일 단위 | 없음 (별도 과제) |

Claude 자체는 어느 단계에서도 학습하지 않습니다. 학습이라고 부르는 것은 전부 우리 장비에서 돌리는 로컬 모델입니다.

---

## 4. 데이터는 지금부터 쌓입니다

모든 단계의 재료는 같습니다: **검수자가 판정을 남긴 실제 작업**. 운영 중 아래만 지키면 별도 라벨링 프로젝트 없이 데이터가 모입니다.

- "검토 필요" 건은 검수 큐에서 반드시 최종 판정을 남긴다.
- 메모에 확인한 하자 코드를 `#코드` 형식으로 적는다(예: `#exposed_wiring 확인`). 이 태그가 하자 라벨이 됩니다.
- 사진 보관을 켠다(`INSPECTOR_PHOTO_STORE_DIR`). 보관이 꺼져 있으면 판정만 남고 사진이 없어 학습·평가에 못 씁니다.
- 기사 앱은 원본 사진(EXIF 포함, HEIC 가능)을 올린다.

---

## 5. 의사결정 기준 요약

- 0단계 결과가 목표(예: 심각 하자 재현율 0.9, 전체 정밀도 0.8)를 넘으면 학습 없이 운영합니다.
- 특정 하자만 부족하면 1→2단계. 고정 구도 컷에서 미세 결함이면 3단계.
- 외부 전송 불가 결정 또는 월 토큰 비용이 로컬 GPU 운영비를 넘으면 4단계 검토.
- 어떤 단계든 전후를 0단계 리포트로 비교해 숫자로 판단합니다.
